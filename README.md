# Документальное телевидение · 0.5.0

Статический одноканальный сайт с общей программой по времени Минска (UTC+3). Сайт публикуется через GitHub Pages из ветки `main`. Видеопоток идёт напрямую от источника к зрителю.

## Эфир

- YouTube-видео и прямые HTTPS-видеофайлы воспроизводятся как единый телеканал.
- Сохранена исходная обрезка YouTube сверху и снизу в `assets/style.css`.
- Все документальные передачи начинаются только ровно в начале часа. Если фильм закончился в 20:17, до 21:00 автоматически включается одна из веб-камер, а следующая документальная передача стартует в 21:00.
- За восемь секунд до начала показывается эфирный идентификатор DOC TV: время старта, тип передачи/цикл, название и отметка «ПРЕМЬЕРА» при первом показе.
- Переходы сделаны через отдельный слой затемнения: окончание фильма мягко уходит в чёрный, затем появляется экран перерыва/ident, а новое видео проявляется только после фактического запуска плеера.
- Первый показ нового видео автоматически получает отметку «ПРЕМЬЕРА».
- Настройки громкости и mute сохраняются в `localStorage`.
- YouTube не разрешает автоматически начинать новый ролик в невидимом плеере. Когда зритель возвращается во вкладку, сайт одним вызовом `loadVideoById()` переключает тот же iframe на актуальную передачу с правильной эфирной секунды, скрывая устаревший кадр до начала воспроизведения. Уже играющую текущую передачу сайт не перематывает.

## Самостоятельное добавление видео (GitHub Actions)

Добавлять новые видео можно без правки JSON и без стороннего сервера:
[GitHub Actions → Add video to DOC TV](https://github.com/byatheism/web-tv/actions/workflows/add-video.yml).

1. Выберите **Add video to DOC TV**, затем **Run workflow** и ветку **main**.
2. Вставьте YouTube-ссылку в **source**. Параметр **kind**: `video` для отдельного ролика или `playlist` для всего плейлиста (до 60 видео за один импорт).
3. В **media_type** выберите: `documentary` — обычный фильм, `game` — игровая история, `stone` — Stone Simulator, `webcam` — живая подводная камера. Веб-камеры можно импортировать только по одной.
4. Для игрового плейлиста **обязательно** заполните **series** — название игры. Для отдельной серии можно задать **episode** (если оставить пустым, будет выбран следующий номер). **title** позволяет заменить название одного ролика. **duration_seconds** — необязательная длительность в секундах, если YouTube не сообщает хронометраж.
5. Нажмите **Run workflow** и откройте журнал нового запуска. Скрипт проверит адрес, получит метаданные, исключит дубликаты, обновит только `data/videos.json` и выполнит `npm test` и `npm run check`.
6. Автоматизация создаст **Pull Request**. Откройте вкладку **Pull requests**, проверьте названия и длительности и подтвердите кнопкой **Merge pull request**. Пока вы не подтвердили, эфир не меняется. После слияния автоматически пересобирается трёхдневное расписание.
7. Если GitHub запрещает создание Pull Request роботом, в отчёте будет ссылка **Create pull request** для ручного оформления. По желанию разрешите это в **Settings → Actions → General → Workflow permissions → Allow GitHub Actions to create and approve pull requests**.

**Безопасность:** задание доступно пользователям с правом запуска workflow в репозитории. Используется временный встроенный `GITHUB_TOKEN`, а не личный токен в браузере; токены никогда не добавляются в GitHub Pages. Принимаются только прямые URL YouTube. Скрипт не выполняет команды из введённых полей, не изменяет исходники и не публикует видео сразу. Вся правка ограничена `data/videos.json`. Если метаданные недоступны или проверка не пройдена — Pull Request не создаётся. Права для слияния и история коммитов остаются стандартными для GitHub.

Новые игровые серии включаются в существующую группу «Игровые истории», а Stone Simulator и подводные камеры остаются только отбивками между программами. Строго последовательное чередование всех серий больших игровых прохождений потребует отдельной доработки генератора ротации: номер серии уже хранится, но группа игровых историй пока выбирает ролики по давности показа.

## Автоматическая программа и фиксация сетки

`data/schedule.json` содержит опубликованную историю и правила ротации. `assets/schedule.js` умеет строить продолжение сетки автоматически.

Отдельный GitHub Action `Freeze programme` поддерживает файл `data/fixed-schedule.json`: ближайшие три суток программы заранее сформированы и зафиксированы. Поэтому обычная перезагрузка страницы не переставляет будущие передачи.

Правила фиксации:
- фиксированное окно ежедневно продлевается примерно до трёх суток вперёд;
- Action запускается автоматически при изменении `data/videos.json`, `data/schedule.json`, генератора или логики расписания;
- если добавлены новые видео, уже начавшийся показ сохраняется, а ещё не начавшаяся часть будущей сетки может быть автоматически перестроена с учётом нового материала;
- сайт проверяет набор ID каталога, поэтому даже добавление видео без ручного изменения версии не заставит его использовать устаревшее будущее;
- после конца зафиксированного окна сайт всё равно умеет динамически достроить дальнейшую программу;
- документальные передачи фиксируются только на отметках `:00`; промежутки до следующего полного часа автоматически заполняются живыми веб-камерами.

Ротация:
- чередует независимые документальные группы и не ставит одну группу два раза подряд;
- продолжает циклы с серии, следующей за последней уже показанной;
- для самостоятельных фильмов выбирает наиболее давно не показывавшийся;
- не повторяет одно и то же видео раньше заданного интервала (`minRepeatHours`, сейчас 8 часов);
- автоматически подхватывает новые серии существующих циклов и новые фильмы документальной подборки;
- динамический резерв программы строится минимум на семь суток вперёд;
- Stone Simulator и веб-камеры не участвуют в премьерах и повторной защите документалок; Stone Simulator выбирается под длительность паузы, а веб-камеры служат запасным наполнением;
- новые записи Stone Simulator из YouTube-плейлиста `PLCvU3DgR5rsE` подхватываются ежедневным GitHub Action `Sync Stone Simulator playlist`. Для обновления вручную запустите его через Actions.

Сейчас в ротации пять направлений: «Цивилизация», «Великие географические открытия», «Земля BBC», самостоятельные документальные фильмы и «Игровые истории». В игровую группу входят выпуски по One-Eyed Likho, INDIKA, Kingdom Come: Deliverance II и две последовательные части Crime Scene Cleaner. **Основные отбивки — прямые трансляции подводного мира.** Stone Simulator появляется примерно в каждом третьем подходящем перерыве: записи отдельного плейлиста подбираются только если их оставшаяся длина покрывает всю паузу с небольшим запасом. Для записей длиннее 30 минут стартовый фрагмент выбирается псевдослучайно, но одинаково для всех зрителей. Если подходящего каменного видео нет, продолжают работать пять live-веб-камер explore.org.

Каталог передач хранится в `data/videos.json`. Обязательные поля: `title`, `durationSeconds`, `source`. Для циклов используются `series` и `episode`; для непрерывных камер используется `live: true`.

## Интерфейс телевизора

Корпус телевизора остаётся функциональным, но получил более аккуратную аппаратную отделку: многослойную рамку, более глубокую нишу экрана, стеклянный блик и виньетирование без декоративных кружков, переработанную решётку динамика и нижнюю панель, и аккуратный встроенный регулятор громкости без лишних подписей.

## Проверки и разработка

Node.js 22+:

```
npm test
npm run check
```

CI дополнительно проверяет синтаксис `assets/player.js` и `assets/schedule.js`. Тесты контролируют пересечения, часовые стартовые отметки документалок, заполнение пауз веб-камерами, порядок серий, ротацию, премьеры, защиту от частых повторов и совместимость фиксированной сетки с каталогом.

Основные модули:
- `assets/schedule.js` - проверка данных, ротация и объединение фиксированной/динамической программы;
- `scripts/freeze-programme.js` - генерация трёхдневной фиксированной сетки;
- `data/fixed-schedule.json` - автоматически поддерживаемый снимок ближайшей программы;
- `assets/media.js` - YouTube / HTML video;
- `assets/player.js` - эфир, ident, мягкие переходы и восстановление воспроизведения;
- `assets/common.js` - общие функции интерфейса;
- `assets/style.css` - корпус телевизора и исходная обрезка YouTube;
- `assets/features.css` - эфирные заставки, переходы и дополнительные стили.
